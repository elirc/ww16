# Deal transition lab

This course follows the active ww16 service and its production policy. `dealRegistrationService.transitionDeal` pre-reads a visible deal, invokes `assertDealTransitionAllowed`, then starts a transaction using one client for status update, approval history, audit, and conditional jobs. The session carries `role`; permissions are derived by the real authorization helper. The lab covers SALES_REP sales approval, channel approval, invalid edges, missing deals, update failure, and audit failure. Read the source and runtime test before making claims. The captured test uses explicit adapters, so it teaches orchestration without pretending to run Prisma.

Use this as a small service-review workshop. First predict the output of a SUBMITTED deal changing to SALES_APPROVED. Then run the lab and compare its history payload to your prediction. Next change the actor from SALES_REP to PARTNER_SELLER and explain the refusal using the actual permission helper. Finally examine an audit failure and distinguish attempted calls from committed records. These are separate learning methods: prediction, executable feedback, code tracing and failure analysis. No production behavior was changed. The database and repositories are adapters; actual policy, errors and quarter formatting execute from source. Read [the test](../tests/deal-transition-lab.test.mjs) with [the service](../src/services/dealRegistrationService.ts), then attempt the exercises before the answers.
