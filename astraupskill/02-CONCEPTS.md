# Concepts

A workflow edge has two dimensions: state adjacency and role authorization. A SALES_REP can approve sales when the current state is SUBMITTED, while channel approval requires the appropriate role and current state. Approval history is durable evidence of the edge, and audit is a separate record. The service deliberately reads before the transaction, so the test can verify that policy uses the observed current status. Same-client assertions prove adapter discipline, not database rollback. Concurrent writers remain a limitation.

Consider two sales representatives reading SUBMITTED concurrently. Each policy check can pass before either transaction starts. Grouping writes into transactions does not by itself compare the old status at write time. A conditional update containing expected status, a version column, or an appropriate locking design could address this; each requires provider-backed tests. The current lab deliberately does not implement that redesign. Approval history records who attempted which transition with a note, while an audit event supports operational investigation. Neither record should be described as a lock. The queued leaderboard job is another persisted request; inserting it does not prove a worker ran or a leaderboard changed. Separating these concepts prevents a junior developer from mistaking a successful service return for completion of every downstream effect.
